# Manga Drama Studio 产品脑暴

日期：2026-07-19

## 1. 问题定义

漫剧生产不是一次模型调用，而是一条可反复调整的媒体流水线：故事拆解、角色定妆、分镜、画面、配音、动效、字幕、合成。传统表单无法清楚表达依赖关系，也难以局部重跑，因此采用类似 ComfyUI 的节点工作流最合适。

## 2. 产品原则

1. **工作流是核心资产**：创作过程可保存、复制、版本化和复跑。
2. **角色一致性优先**：角色设定和参考图作为独立节点，被所有分镜复用。
3. **可观察、可恢复**：每个节点有独立状态、耗时、日志和输出；失败后可从失败节点继续。
4. **供应商可替换**：LLM、绘图、视频、TTS 都通过统一执行器接口接入。
5. **Token 可治理**：密钥不回显，可按能力、权重和健康状态选择渠道，并预留成本账单。

## 3. 用户与核心旅程

目标用户是个人漫剧创作者和小型内容团队。最短成功路径：

1. 新建项目，填写作品名与一句话设定。
2. 从示例工作流开始，在画布中调整节点与连线。
3. 配置模型渠道 Token，选择各节点使用的能力。
4. 运行工作流，通过实时事件查看节点进度。
5. 在资产区查看图片、音频、视频并导出成片。

## 4. MVP 范围

### 本期实现

- 项目列表与创建。
- ComfyUI 风格节点画布，支持拖动、连线、增删节点、属性编辑和保存。
- 节点类型：故事输入、剧本拆解、分镜规划、角色设定、画面生成、配音、视频合成。
- 有向无环图校验：端口存在、类型兼容、必填输入、重复边和环检测。
- 运行任务、节点级状态、SSE 实时事件和失败取消能力。
- Provider Token 管理：新增、启停、掩码展示；MVP 执行器为可演示的 mock。
- 本地零依赖数据持久化、Docker 构建和示例工作流。

### 明确不做

- 多租户、支付计费、团队协作和细粒度权限。
- 内置真实模型厂商适配器与生产级密钥托管。
- GPU 调度、分布式队列、断点续跑和成片时间轴编辑器。
- 工作流版本合并、插件市场和节点沙箱。

## 5. 技术决策

- Go 后端采用标准库，减少 MVP 基础设施和依赖；以 repository 接口隔离存储，后续可换 SQLite/PostgreSQL。
- 前端采用 Vue 3 + Vue Flow，画布体验接近 ComfyUI；Pinia 管理编辑状态。
- SSE 用于单向进度流，比 WebSocket 更贴合任务事件且部署简单。
- 首版执行器按拓扑层级串行运行，结构上保留并行调度空间。
- Token 以应用密钥加密后持久化；缺少安全密钥时禁止创建真实渠道。

## 6. 后续路线

- P1：OpenAI 兼容 LLM、ComfyUI API、TTS、FFmpeg 适配器；资产管理与节点重跑。
- P2：Redis 队列、worker、对象存储、费用估算、渠道负载均衡。
- P3：多人协作、模板市场、时间轴精编、审核发布与运营数据。
